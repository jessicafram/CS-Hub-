Módulo 8: TypeScript e Tipagem de APIs

Como garantir contratos seguros entre cliente e servidor e evitar bugs silenciosos na produção.

Até agora aprendemos:

  • arquitetura da aplicação
  • consistência de dados
  • idempotência
  • resiliência
  • segurança de acesso

Agora vamos entender um tema fundamental no desenvolvimento moderno de APIs:
Como garantir que os dados da aplicação tenham o formato correto?

Esse problema é resolvido usando tipagem estática.

1. O problema do JavaScript puro

Historicamente o Node.js foi desenvolvido usando: JavaScript. JavaScript é uma linguagem dinamicamente tipada.

Exemplo:

JavaScript 
let value = 10
value = "dez"
value = true

Isso funciona. Mas em aplicações grandes pode causar erros difíceis de detectar. Exemplo em uma API:

JavaScript 
amount = "200"

Em vez de:

JavaScript 
amount = 200

Isso pode gerar erros financeiros.

🎮 Interativo: O Escudo de Tipagem na Prática

Clique nos botões abaixo para simular o que acontece quando o front-end envia acidentalmente o "amount" (valor) como uma String "200" em vez de um Número 200 para somar com uma taxa de 50.

let amount = "200"; // O JS aceita qualquer coisa
let total = amount + 50; // O cliente espera pagar 250
console.log(total);

// 🚨 RESULTADO SILENCIOSO NA PRODUÇÃO:
"20050" (Concatenou! Cliente cobrado R$ 20.050,00)
let amount: number = "200"; // ❌ ERRO IMEDIATO NO VS CODE

// 🛡️ O TypeScript trava o build do projeto antes de ir para o ar e avisa:
Error: Type 'string' is not assignable to type 'number'.

2. O que é TypeScript

Para resolver esses problemas foi criado: TypeScript. TypeScript é um superset do JavaScript que adiciona tipagem estática.

Exemplo:

TypeScript 
let amount: number = 200

Agora se alguém tentar: amount = "200" O compilador gera erro.

3. Benefícios da tipagem em APIs

Usar TypeScript em APIs traz vários benefícios.

  • segurança de tipos: dados com formato incorreto são detectados antes de rodar
  • refatoração segura: alterar código sem quebrar partes invisíveis
  • melhor colaboração em equipe: tipos funcionam como documentação

4. Tipos como contrato de API

Em APIs modernas, tipos funcionam como um contrato entre cliente e servidor. Exemplo de contrato:

TypeScript 
interface CreateTransactionRequest {
    products: ProductInput[]
    card_info: CardInfo
}

Isso define exatamente: quais campos são esperados.

5. Validação de dados

Mesmo com TypeScript, precisamos validar dados vindos do cliente. Porque o cliente pode enviar qualquer coisa. Por isso frameworks usam validators. No seu projeto você utilizou: vine validator.

Exemplo:

TypeScript 
export const signupValidator = vine.create({
    email: vine.string().email(),
    password: vine.string().minLength(8)
})

Isso garante: email válido, senha com tamanho mínimo.

6. Boundary da aplicação

Uma prática importante em APIs é validar dados no boundary da aplicação. Boundary significa: entrada da API.

Fluxo ideal:
Request → Validator → Controller → Service

Isso impede que dados inválidos avancem para a lógica de negócio.

7. Tipagem dentro da aplicação

Dentro do código usamos tipos para modelar dados internos. Exemplo no seu projeto: PaymentResult.

Esse tipo pode representar algo como:

TypeScript 
interface PaymentResult {
    success: boolean
    gateway: string
    externalId?: string
}

Isso garante que o service sempre retorne um formato previsível.

8. Tipagem das respostas da API

Outra boa prática é tipar as respostas da API. Exemplo:

TypeScript 
interface TransactionResponse {
    id: number
    totalAmount: number
    gateway: string
}

Isso cria um contrato claro para clientes da API.

9. Conectando com seu projeto

No seu sistema TypeScript aparece em vários pontos:

  • Controllers: TransactionsController
  • Services: PaymentService
  • Models: Transaction, Product, User
  • Validators: signupValidator, loginValidator

Isso mostra que seu projeto utiliza tipagem em toda a aplicação.

10. Problema real resolvido

Sem tipagem podemos ter problemas como:

  • valor enviado como string
  • campo inexistente
  • erro de estrutura no payload

Com TypeScript esses erros são detectados antes da execução.

11. Conectando com entrevistas

Uma pergunta comum em entrevistas é: "Por que você escolheu TypeScript para esse projeto?"

👉 Clique para revelar a Resposta madura

Eu escolhi TypeScript porque ele melhora a segurança do código através de tipagem estática. Em uma API de pagamentos isso é especialmente importante, pois ajuda a evitar erros de tipo em dados financeiros e garante contratos claros entre as camadas da aplicação. Além disso, facilita refatorações e melhora a colaboração em equipe.
