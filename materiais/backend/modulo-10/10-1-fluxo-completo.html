Módulo 10: Anatomia Completa do Fluxo de Pagamento

O que realmente acontece milissegundo a milissegundo quando um cliente clica em "Comprar".

  • arquitetura

  • consistência de dados

Agora vamos analisar o fluxo completo de um pagamento dentro da sua API.
A pergunta central deste módulo é:
O que realmente acontece dentro do sistema quando um cliente clica em "Comprar"?

Vamos percorrer cada etapa da requisição, conectando com o seu código.

1. A requisição do cliente

Tudo começa com uma requisição HTTP. Exemplo:

JSON 
POST /transactions

{
  "products": [
    { "id": 10, "quantity": 2 },
    { "id": 15, "quantity": 1 }
  ],
  "card_info": {
    "cardNumber": "4111111111111111"
  },
  "client_id": 3
}

Essa requisição representa: um checkout.

2. Entrada na API

A requisição chega no servidor e passa primeiro pela camada de roteamento. Arquivo: routes.ts

Fluxo:
Request → Route → Controller

3. Middleware de autenticação

Antes de chegar ao controller, a requisição passa por middlewares.

Fluxo:
Request → Auth Middleware → Role Middleware → Controller

Aqui o sistema verifica: usuário autenticado e permissão de acesso. Se falhar: HTTP 401 ou 403.

4. Controller recebe a requisição

Agora o controller entra em ação. Arquivo: TransactionsController

Função principal:

TypeScript 
async store({ auth, request, response })

Responsabilidades do controller: ler dados da requisição, verificar idempotência, preparar dados, chamar serviço e retornar resposta.

5. Verificação de idempotência

Primeiro passo dentro do controller:

TypeScript 
const idempotencyKey = request.header('Idempotency-Key')
const existingTransaction = await Transaction.findBy('idempotencyKey', idempotencyKey)

Fluxo: Idempotency-Key existe? se sim, retornar transação existente; se não, continuar fluxo. Isso evita pagamentos duplicados.

6. Validação do carrinho

O controller verifica os produtos.

Fluxo: receber lista de produtos → buscar produtos no banco → validar existência.
Trecho do fluxo: Product.find(product_id). Se um produto não existir: HTTP 404.

7. Cálculo do valor total

O valor do pagamento não vem do cliente. Ele é calculado no backend.

Fluxo: preço do produto X quantidade. Isso evita manipulação maliciosa.

8. Chamada do PaymentService

Agora o controller delega o processamento.
Controller → Payment Service

Chamada: PaymentService.processPayment(...) Aqui começa a lógica de negócio principal.

A Cereja do Bolo

8.5 Resiliência Preditiva com IA (Z-Score)

Sistemas normais esperam o gateway cair (Timeout) para fazer o Failover. Na sua arquitetura avançada, implementamos um Middleware de IA Preditiva.

O sistema analisa a latência histórica do gateway em tempo real. Utilizando o cálculo estatístico Z-Score, o sistema detecta anomalias de lentidão e redireciona a requisição para o Gateway de Backup antes mesmo que a falha em cascata aconteça!

9. Comunicação com gateways e Failover

Se o gateway principal falhar (ou se nossa IA Preditiva desviar a rota):
Gateway 1 falha → Gateway 2. Isso aumenta a disponibilidade do sistema.

10. Início da transação de banco e Persistência

O gateway retorna approved. Agora entramos na parte crítica do sistema.

Fluxo: BEGIN TRANSACTION. Isso ativa as propriedades: ACID.
Criamos a Transaction (evento financeiro) e os TransactionProducts (itens do carrinho).

Se tudo funcionar: COMMIT. Se ocorrer erro: ROLLBACK.

12. Pergunta final de entrevista

"Você pode explicar o fluxo completo de pagamento na sua API?"

👉 Clique para revelar a Resposta madura

O fluxo começa quando o cliente envia uma requisição de checkout. O controller recebe a requisição, verifica a idempotência e valida os produtos do carrinho. Em seguida delega o processamento para o PaymentService, que tenta processar o pagamento através de um gateway e realiza failover caso necessário. (Como bônus, implementei uma IA preditiva com Z-Score que monitora a latência e antecipa o failover preventivamente). Após a confirmação do pagamento, iniciamos uma transação de banco para persistir os dados da compra e os produtos associados. Se todas as operações forem bem-sucedidas, a transação é confirmada e a API retorna a resposta ao cliente.
