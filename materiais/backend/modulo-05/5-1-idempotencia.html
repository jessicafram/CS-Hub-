Módulo 5: Idempotência e Requisições Duplicadas

Como evitar cobrar um cliente duas vezes em cenários de lentidão de rede e múltiplos cliques.

Agora que entendemos:

  • arquitetura da API
  • modelagem do banco
  • transações ACID

precisamos resolver um problema clássico da internet:

Como evitar que o mesmo pagamento seja processado mais de uma vez?

Esse problema ocorre com frequência em sistemas distribuídos.

1. O problema das requisições duplicadas

Imagine um cenário real. Um cliente está comprando pelo celular com internet lenta.

Fluxo:

  • Usuário clica em "Comprar"
  • requisição enviada
  • a tela demora para responder
  • usuário clica novamente

Agora sua API recebe:

HTTP 
POST /transactions
POST /transactions

Duas requisições quase simultâneas. Sem proteção isso pode gerar: duas cobranças no cartão. Esse é um problema extremamente sério em sistemas financeiros.

2. Por que isso acontece na internet

A internet é um ambiente não confiável. Requisições podem ser duplicadas por vários motivos:

  • usuário clicando várias vezes
  • timeout de rede
  • retry automático do navegador
  • retry automático do cliente HTTP
  • balanceadores de carga

Isso significa que o servidor pode receber: a mesma requisição múltiplas vezes.

3. O conceito de idempotência

Para resolver esse problema usamos um conceito chamado: Idempotência.

Definição simples:

Uma operação pode ser executada várias vezes sem alterar o resultado final.

Exemplo:

  • executar uma vez → resultado X
  • executar dez vezes → resultado X

No caso de pagamentos: uma cobrança só pode acontecer uma vez.

4. Como APIs implementam idempotência

A solução mais comum é usar um identificador único da requisição. Esse identificador é chamado de: Idempotency-Key.

Fluxo: Cliente envia requisição + Idempotency-Key.

Exemplo:

HTTP 
POST /transactions
Idempotency-Key: 8f9a3c2d-1234

Agora o servidor faz: verifica se essa chave já foi usada.

  • Se for a primeira vez: processa pagamento, salva chave no banco.
  • Se já existir: retorna o resultado anterior.

5. Como seu projeto implementa isso

No seu controller você faz:

TypeScript 
const idempotencyKey = request.header('Idempotency-Key')

Depois:

TypeScript 
const existingTransaction = await Transaction.findBy('idempotencyKey', idempotencyKey)

Fluxo completo:

  1. Recebe requisição
  2. verifica se idempotencyKey existe
  3. se existir retorna transação existente
  4. se não existir processa pagamento

6. Fluxo completo no seu sistema

Fluxo normal:

  • Cliente envia requisição
  • Idempotency-Key recebida
  • verifica no banco → não existe
  • processa pagamento
  • salva transação com a chave

Fluxo duplicado:

  • Cliente envia mesma requisição novamente
  • mesma Idempotency-Key
  • transação já existe
  • API retorna resposta anterior

Resultado: nenhuma cobrança duplicada.

7. Por que salvar a chave no banco

Se a chave fosse armazenada apenas em memória: reiniciar servidor → perder histórico → duplicação possível.

Salvar no banco garante: persistência. Por isso seu modelo Transaction contém: idempotencyKey.

8. Idempotência em APIs reais

Essa estratégia é utilizada por empresas que processam bilhões de transações. Exemplo: Stripe, PayPal.

A API da Stripe inclusive recomenda explicitamente: usar Idempotency-Key em operações financeiras.

9. Por que isso é importante em pagamentos

Sem idempotência podemos ter:

  • cobranças duplicadas
  • pedidos duplicados
  • erros financeiros

Isso gera problemas como: reclamações de clientes, chargebacks, perda de confiança. Por isso sistemas financeiros tratam esse problema com muita seriedade.

10. Limitações da idempotência

Mesmo com idempotência ainda precisamos considerar outros cenários.

Exemplo: mesma requisição, mas chave diferente. Isso pode acontecer se o cliente gerar uma nova chave. Por isso sistemas avançados também usam: correlation IDs, verificação de duplicação lógica. Mas para um desafio técnico sua solução está muito correta.

11. Conectando com seu projeto

Seu sistema resolve o problema de duplicação usando três elementos:

  • header Idempotency-Key
  • persistência da chave
  • verificação antes do processamento

Trecho chave do seu código:

TypeScript 
const existingTransaction = await Transaction.findBy('idempotencyKey', idempotencyKey)

Isso demonstra entendimento de: resiliência em APIs.

12. Pergunta de entrevista (Módulo 5)

"Como sua API evita cobranças duplicadas?"

👉 Clique para revelar a Resposta madura

A API utiliza um mecanismo de idempotência baseado no header Idempotency-Key. Quando uma requisição de checkout é recebida, o sistema verifica se já existe uma transação registrada com a mesma chave. Se existir, a API retorna a transação já processada em vez de executar novamente o fluxo de pagamento. Isso garante que múltiplas requisições idênticas não resultem em cobranças duplicadas.
