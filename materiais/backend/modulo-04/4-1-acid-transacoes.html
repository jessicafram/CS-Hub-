Módulo 4: ACID e Transações de Banco de Dados

Garantindo que operações financeiras não deixem o banco em um estado inconsistente.

Agora que entendemos:

  • o problema dos sistemas de pagamento (Módulo 1)
  • a arquitetura da aplicação (Módulo 2)
  • a modelagem do banco (Módulo 3)

precisamos entender como garantir que os dados financeiros permaneçam consistentes mesmo quando ocorrem erros.

A pergunta central deste módulo é:
Como garantir que operações financeiras não deixem o banco em um estado inconsistente?

Esse é um dos problemas mais importantes em engenharia de sistemas financeiros.

1. O problema da consistência de dados

Imagine o fluxo de checkout do seu sistema. Cliente compra dois produtos: Produto A e Produto B.

Fluxo da aplicação:

  • 1. Criar Transaction
  • 2. Criar Transaction Products
  • 3. Confirmar pagamento

Agora imagine que ocorre um erro no meio: Transaction criada, mas Erro ao salvar Transaction Products.

Resultado: Transaction salva, Produtos não associados. Isso cria dados inconsistentes. Em sistemas financeiros isso é extremamente grave.

2. O conceito de transação de banco

Para resolver esse problema utilizamos transações de banco de dados. Uma transação agrupa múltiplas operações em uma única unidade lógica.

Fluxo conceitual:
BEGIN TRANSACTION
operação 1
operação 2
operação 3
COMMIT

Se algo falhar: ROLLBACK. Ou seja: tudo ou nada.

3. O princípio ACID

As transações de banco seguem um conjunto de propriedades chamadas: ACID. ACID foi definido na teoria de bancos relacionais. Banco utilizado no seu projeto: MySQL.

4. Atomicidade (Atomicity)

Atomicidade significa: uma operação ocorre completamente ou não ocorre.

Exemplo: Transaction criada + TransactionProducts criados. Se qualquer passo falhar: nenhum dado é salvo. Isso evita estados inconsistentes.

5. Consistência (Consistency)

Consistência significa que o banco sempre permanece em um estado válido.

Exemplo: transaction_products.product_id deve existir em products.id. Se uma operação violar uma regra: a transação falha. Isso mantém o banco coerente.

6. Isolamento (Isolation)

Isolamento garante que transações simultâneas não interfiram entre si. Imagine dois usuários comprando ao mesmo tempo (User A, User B). Cada operação ocorre como se fosse isolada. Isso evita problemas como leitura de dados parcialmente atualizados.

7. Durabilidade (Durability)

Durabilidade significa que uma vez que a transação foi confirmada (COMMIT), os dados persistem mesmo em caso de falha do sistema. Exemplo: queda de energia ou crash do servidor. Mesmo assim os dados permanecem salvos.

8. Aplicando ACID no seu projeto

No seu código você implementou transações usando const trx = await db.transaction(). Fluxo no seu controller:

TypeScript 
const trx = await db.transaction()

try {
    const transaction = await Transaction.create(..., { client: trx })
    await TransactionProduct.create(..., { client: trx })
    await trx.commit()
} catch (error) {
    await trx.rollback()
}

Isso significa: Transaction + TransactionProducts = uma única operação lógica. Se qualquer parte falhar: rollback.

9. Fluxo real no seu sistema

Fluxo completo do checkout:

  • Cliente envia requisição → Controller processa pagamento → Gateway aprova
  • BEGIN TRANSACTION → Transaction criada → TransactionProducts criados → COMMIT
  • Resposta enviada

Se ocorrer erro: BEGIN TRANSACTION → Transaction criada → Erro ao salvar produtos → ROLLBACK (nenhum dado salvo).

10. Problemas reais resolvidos

O uso de transações resolve vários problemas importantes:

  • inconsistência de pedidos (pedido sem produtos)
  • inconsistência financeira (pagamento aprovado sem registro)
  • erros parciais (metade da operação salva)

11. Conectando com seu domínio de pagamento

Seu sistema executa duas operações críticas: persistência da transação e associação de produtos. Ambas precisam ocorrer juntas. Por isso você agrupou em uma transação. Isso demonstra boa prática em sistemas financeiros.

12. Pergunta de Entrevista (Módulo 4)

"Por que você usou uma transação de banco no fluxo de checkout?"

👉 Clique para revelar a Resposta madura

O fluxo de checkout envolve múltiplas operações de persistência, como criar a transação e associar os produtos comprados. Utilizar uma transação de banco garante que essas operações ocorram de forma atômica. Caso qualquer etapa falhe, o rollback desfaz todas as alterações, evitando inconsistências no banco de dados.
