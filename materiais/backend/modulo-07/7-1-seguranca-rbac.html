Módulo 7: Segurança e Controle de Acesso (RBAC)

Como garantir que apenas os usuários corretos tenham permissão para executar operações críticas.

Até agora aprendemos:

  • arquitetura da aplicação
  • consistência de dados
  • idempotência
  • resiliência do sistema

Agora precisamos resolver outro problema essencial:

Quem pode executar cada operação dentro do sistema?

Em sistemas financeiros, permitir acesso incorreto pode causar problemas graves.

1. O problema do controle de acesso

Imagine que sua API possui operações como:

  • criar pagamento
  • consultar transação
  • executar chargeback

Agora imagine o seguinte cenário:

usuário comum executa um chargeback

Resultado possível:

  • reversão indevida de pagamentos
  • fraudes
  • inconsistência financeira

Por isso sistemas precisam de controle de acesso.

2. Autenticação vs Autorização

Esses dois conceitos são frequentemente confundidos.

Autenticação

Pergunta: quem é o usuário?

Exemplo:

  • login
  • token
  • senha

No seu projeto isso ocorre através do sistema de autenticação do: AdonisJS

Autorização

Pergunta: o que esse usuário pode fazer?

Exemplo:

  • usuário pode criar pagamento
  • usuário NÃO pode executar chargeback

Autorização define permissões dentro do sistema.

3. O modelo RBAC

Uma forma comum de implementar autorização é o modelo: RBAC

Significado: Role-Based Access Control

Nesse modelo, cada usuário possui um papel (role).

Exemplo:

  • ADMIN
  • MANAGER
  • FINANCE
  • USER

Cada role possui permissões diferentes.

4. Papéis no seu sistema

No seu projeto você definiu quatro papéis.

Role Permissões
ADMIN acesso total
MANAGER operações administrativas
FINANCE operações financeiras
USER realizar compras

Isso define quem pode acessar cada funcionalidade da API.

5. O princípio do menor privilégio

Uma regra importante em segurança é: Principle of Least Privilege

Significado: cada usuário deve ter apenas as permissões necessárias

Exemplo:

  • usuário comum: apenas comprar
  • financeiro: pode executar chargeback

Isso reduz riscos de abuso ou erro.

6. Middleware de autorização

Em APIs modernas, o controle de acesso geralmente ocorre através de middleware.

Middleware é um componente que intercepta requisições antes do controller. Fluxo:

Fluxo de Request 
Request
  ↓
Auth Middleware
  ↓
Role Middleware
  ↓
Controller

No seu projeto existem middlewares como:

  • auth_middleware
  • role_middleware

7. Como o middleware funciona

Quando uma requisição chega:

Fluxo:
POST /transactions/chargeback

  1. 1. verificar autenticação
  2. 2. verificar role
  3. 3. permitir ou negar acesso

Se o usuário não tiver permissão: HTTP 403 Forbidden

8. Fluxo de segurança no seu sistema

Fluxo completo:

Pipeline de Segurança 
Cliente faz requisição
  ↓
Auth Middleware
  ↓
verifica token
  ↓
Role Middleware
  ↓
verifica role do usuário
  ↓
Controller executa operação

Representação simplificada:

Request → Authentication → Authorization → Business Logic

9. Protegendo operações críticas

Operações críticas no seu sistema incluem:

  • chargeback
  • operações administrativas

Essas operações devem ser restritas a roles específicas. Exemplo: FINANCE, ADMIN.

Isso impede que: usuário comum manipule pagamentos.

10. Como isso aparece no seu projeto

No seu sistema o controle de acesso ocorre antes do controller.

Router Config 
Route
  ↓
Middleware de autenticação
  ↓
Middleware de role
  ↓
TransactionsController

Se o usuário tiver permissão: requisição continua. Caso contrário: erro de autorização.

11. Benefícios do RBAC

Implementar RBAC traz vários benefícios.

  • segurança: acesso restrito a operações sensíveis
  • organização: permissões claras
  • escalabilidade: novos papéis podem ser adicionados

12. Limitações do RBAC

Embora RBAC seja muito usado, ele possui limitações. Exemplo: permissões muito específicas.

Nesses casos sistemas avançados usam modelos como: ABAC. Significado: Attribute-Based Access Control.

Mas para a maioria das APIs RBAC é suficiente.

13. Conectando com seu projeto

Seu sistema protege operações financeiras utilizando: RBAC + middleware de autorização.

Fluxo final:
Request → Auth Middleware → Role Middleware → TransactionsController

Isso impede que usuários não autorizados executem ações críticas.

14. Pergunta de entrevista (Módulo 7)

"Como você protege operações sensíveis na sua API?"

👉 Clique para revelar a Resposta madura

A API implementa controle de acesso baseado em papéis (RBAC). Cada usuário possui uma role associada, como ADMIN, MANAGER, FINANCE ou USER. Um middleware de autorização verifica a role do usuário antes que a requisição alcance o controller. Dessa forma garantimos que apenas usuários autorizados possam executar operações críticas como chargebacks.
